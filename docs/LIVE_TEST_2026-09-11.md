# Gemini 3.8 병렬 분석 2회 제한 테스트

- 사용자 승인: 텍스트 문제 한 건, 모델 호출 최대 2회. 재시도 없음.
- 모델: gemini-3.8-flash. 로컬 전용 worker/live-two-call.ts에서 parallel / retries=0 강제.
- 운영 배포 없음. 이미지 OCR·유사 문제 생성·단일 모드 비교는 실행하지 않음.
- 입력: x^2 - 5x + 6 = 0, 학생 풀이 (x-2)(x-3)=0 → x=2 또는 x=3.
- requestId: e567c762-3dae-46de-9fe7-f93398c2d4ef

보고된 일부 usage: 입력 271, 생성 출력 503, 사고 2,746, 합계 3,520 토큰.
usageComplete=false이므로 전체 비용으로 합산하지 않음. 이 보고분만 현재 설정 단가로 계산하면 약 $0.012387이며 실패 호출의 청구 여부 및 실제 총 청구액은 확인하지 못함.

두 분기를 동시에 실행했고 각각 한 번씩 호출했다는 점은 확인. 최종 풀이를 반환하지 못했으므로 분석 성공·수학적 정확성·완료 시간 개선을 입증하지 못함. 추가 모델 호출은 사용자 승인 전까지 실행하지 않음.

## 3.8 재실행

- 사용자 요청으로 같은 조건(텍스트 1건, 병렬 2분기, 재시도 0회)으로 gemini-3.8-flash를 다시 실행.
- requestId: 4b394f2a-1b2e-4421-9cc9-ef1c8599b382
- 최대 2회 호출 확인: core 1회(약 4.0초), extensions 1회(약 5.5초)
- 두 호출 모두 모델 응답과 usage metadata를 반환했지만, 병합 전 애플리케이션 검증에서 INVALID_MODEL_OUTPUT으로 거절되어 HTTP 502 반환.
- Worker 로그상 analysis.parallel.failed만 기록되어 있어, 저장되지 않은 모델 원문 없이 어느 필드가 실패했는지 확정할 수 없음. Google 503은 이번 재실행에서는 관측되지 않음.
- 응답 결과가 없으므로 3.8 모델의 수학 품질이나 완료 시간 개선은 판단하지 않음. 추가 호출 없이 로컬 Worker를 종료.

## 결제 계정 추가 후 전체 병렬 통합 테스트

- 실행 조건: `gemini-3.8-flash`, `parallel`, 분기별 최대 재시도 1회.
- 로컬 전용 `worker/live-full-parallel.ts`로 모델·재시도·비용 환경변수를 고정했다. 운영 Worker에는 배포하지 않았다.
- 분석 요청은 `core(student + standard + feedback)`와 `extensions(shortcut + genius + missingPaths)`를 동시에 시작했다.
- 텍스트·이미지 분석은 확장 분기에서 1회 재시도했고, 연습문제는 1회 호출했다. 총 Gemini 호출 수는 7회였다.

## 후속 보완

- 첫 응답과 재시도까지는 선택 경로 누락을 엄격히 검증한다.
- 마지막 재시도에서도 `shortcut` 또는 `genius`가 생성되지 않았고 `missingPaths` 사유만 빠진 경우, 표준 풀이를 유지한다는 투명한 누락 사유를 서버에서 보완해 502 대신 정상 응답한다.
- 실제 upstream 오류, 표준 풀이 누락, 잘못된 JSON은 여전히 실패로 처리하며 분기별 안전한 진단 정보만 로컬 로그에 남긴다.
